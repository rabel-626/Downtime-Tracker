# Downtime Tracker — Work Instructions

## 1. Purpose

Provide a repeatable method for collecting and reviewing downtime observations.

## 2. Study Setup

Complete the identifying fields in **Study Information**. Use a naming convention that allows the study to be traced to the line, job, date, and shift.

## 3. Reason-Code Setup

Review the active downtime categories and causes before beginning the observation. Add definitions or notes where operators or reviewers may interpret a code differently.

## 4. Observation

Start the study window. When a qualifying downtime event occurs, begin the event, select the applicable reason, and end the event when production resumes. Use event notes for unusual context rather than creating ad-hoc reason codes during the study.

## 5. Review

Before export:

- Review event durations.
- Check for missing or implausible entries.
- Review data-quality warnings.
- Confirm included and excluded causes.
- Review Pareto ranking and study-scope production context.

## 6. Save and Export

Save the study JSON first. Then create CSV, Excel-oriented, or report outputs as required by the workflow.

## 7. Record Retention

Retain the JSON alongside any exported report when the analysis may need to be reproduced later.
